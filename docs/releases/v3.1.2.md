# GenOps v3.1.2

> Fixes the global MCP server breaking after a system Python is deleted or upgraded.

## Problem

`install_global.py` wrote `sys.executable` — the absolute path to whichever Python
ran the installer — as the `command` for the `genops` MCP server on every agent
(Gemini/Antigravity, Claude Code, OpenCode, Cline). Removing that Python version
left a dangling interpreter reference, and the MCP server failed at spawn with
CPython's `Could not find platform independent libraries <prefix>` / `PYTHONHOME`
error. A secondary bug pointed the CLI wrapper and MCP args at `install_global.py`
itself rather than the engine.

## Fix

1. **Stable home** — the engine and its bundled assets are copied into `~/.genops/`,
   independent of the source repository.
2. **Self-healing launcher** — `~/.genops/bin/genops` re-resolves and validates a
   working interpreter on every launch (`python3` → `python` → `py -3`), then execs
   the engine. No interpreter path is ever baked, so deleting/upgrading Python is a
   non-event.
3. **Agent-correct MCP shape** — `type: stdio` for Claude Code/OpenCode,
   `disabled`/`autoApprove` for Cline, plain `command`/`args` for Gemini.
4. **Install-time self-test** — the installer verifies the engine is present and
   exposes the `mcp` subcommand before reporting success.
5. **CWD-independent MCP server** — the server starts regardless of the current
   directory, reads workspace roots from the MCP `initialize` handshake, and resolves
   the GenOps project root per request. Missing projects yield a clear per-tool error
   instead of terminating the server.

## Migration

```bash
python .agents/scripts/install_global.py
```

This regenerates every agent's MCP config to point at the new launcher. Agents
that were already running should be restarted to pick up the change.
